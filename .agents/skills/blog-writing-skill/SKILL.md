# Blog Writing Skill

## 写作目标

写出可以照着完成操作的中文教程。正文应自然、具体、可验证，避免营销腔、AI 套话和无意义的铺垫。

默认适配当前 Momo/Astro 博客的 Markdown 格式。创建新文章或大幅重构文章时，读取 [教程模板](references/tutorial-template.md)。

## 开始前

先确认文章所需事实是否齐全。以下信息缺失且会影响正确性时，先向用户提问：

- 教程最终要完成的结果；
- 使用的平台、系统、软件与版本；
- 官方网站、控制台、下载页、文档和代码仓库地址；
- 价格、套餐、优惠、续费价格及适用日期；
- 用户实际执行过的步骤、截图和遇到的错误；
- 是否需要中英文两个版本。

已给出足够信息时直接写，不重复确认。不得猜测网址、仓库、版本、价格、命令输出或产品行为。可能变化的信息需要联网核实，优先使用官网、官方文档和官方仓库。

## 标题与摘要

- 标题只保留最有吸引力的结果、价格或核心动作，通常控制在 8 至 18 个汉字。
- 避免“完整指南”“保姆级教程”“购买与续费避坑”等堆叠式长标题。
- 用户提供标题时优先保留其措辞和口吻；需要压缩时先保留数字与结果。
- 示例：将“低价购买 .com 域名：Google Workspace 购买与续费避坑”压缩为“年费10r顶级域名”。
- `description` 用一句话说明教程覆盖的流程和最终结果，不重复标题，避免空泛宣传。
- 各级小标题应简短、明确、能独立说明本节任务，通常不超过 12 个汉字。

## 结构规则

- 顶级正文分点使用中文编号：`## 一、准备工作`、`## 二、购买域名`、`## 三、检查续费`。
- 顶级章节内部需要再分时，使用：`### 1、打开购买页面`、`### 2、填写信息`。
- 第三级确有必要时使用：`#### （1）选择套餐`、`#### （2）确认价格`。尽量不要继续增加层级。
- 操作步骤内部可以使用 Markdown 有序列表；同级内容保持同一种编号格式。
- 每个操作段落依次给出：入口或网址、具体动作、需要填写的值、预期结果、验证方法。
- 将准备条件放在正式步骤之前，将故障排查和注意事项放在对应步骤之后或文末。

## 教程内容要求

- 给出完整且可点击的网址，不只写“进入官网”。
- 涉及开源项目时给出仓库地址、目标分支或 Release 页面；需要下载时说明下载哪个文件。
- 命令放入代码块，保留准确的路径、参数、配置键、版本号和错误信息。
- Windows、Linux、网页控制台等操作环境应明确区分。
- 每个关键阶段给出成功标志，例如页面提示、文件位置、状态码或终端输出。
- 说明价格时区分首次购买、续费、税费、汇率和优惠期限；没有可靠数据时标记待确认并询问用户。
- 对不可逆、收费、删除、覆盖、密钥暴露等操作，在动作之前给出简短警告。
- 正文以主流程为中心。替代方案、原理和扩展阅读放在主流程之后。

## 语言规则

- 不使用第二人称，包括“你、您、你的、您的、大家”。
- 不使用“我们将”“让我们”“接下来带大家”等主持式表达。
- 直接使用动作句：`打开控制台`、`进入域名设置`、`填写仓库地址`、`确认状态显示为 Active`。
- 使用明确主体描述系统行为：`Cloudflare 会生成一条 CNAME 记录`，避免“它会自动处理”。
- 使用自然、朴素的中文。避免“赋能、解锁、无缝、强大、革命性、深入探讨”等 AI 或营销词。
- 避免空泛开头，例如“在当今数字化时代”。开头直接说明用途、成本、结果或限制。
- 少用冒号和破折号，不连续使用相同句式，不用装腔的总结句。
- 保留用户原稿中有辨识度的词语和实际经历，不擅自润色成宣传稿。

## 写作流程

1. 整理已知事实、缺失信息和需要核实的时效性信息。
2. 确定一个清晰结果，并据此压缩标题和摘要。
3. 先列出“一、二、三”结构，再按真实操作顺序补齐子步骤。
4. 写入网址、仓库、命令、参数、预期结果和验证方式。
5. 最后写简短开头，并删除重复背景和过度总结。
6. 执行发布前检查。

## 发布前检查

- 全文搜索“你、您、大家、我们”，改为直接动作句或明确主体。
- 检查顶级章节是否使用“一、二、三”，内部层级是否一致。
- 检查每个网址、仓库、命令、版本、价格和日期是否真实且仍然有效。
- 检查关键步骤是否包含成功标志和失败后的处理办法。
- 删除 AI 套话、重复解释、空泛转折和装饰性结尾。
- 保留准确的代码、命令、配置键、错误信息和产品名称。
- 更新对应的中文或英文 Markdown；如果项目要求双语但用户只提供一种语言，先询问另一版本是翻译、暂缓还是使用回退。
